## Phase 88: Refactor `harness-work` skill — split SKILL.md, extract templates, dedup with breezing skill

Created: 2026-05-03

**Goal**: Reduce `harness/skills/harness-work/SKILL.md` from 668 lines to ~200 lines by extracting per-mode flows, shared concept docs, and template blocks into `references/` and `templates/` subfolders. Update the `breezing` skill's existing cross-references to point at the new file paths so its delegate-back-to-harness-work pattern keeps working.

**Motivation**: The 668-line SKILL.md is hard to navigate, mixes high-level routing (Quick Reference, Options, mode auto-selection) with deep per-mode flows (solo / parallel / breezing Phase A/B/C), worker-quality contracts (NG rules, self-review gate, universal violations), review machinery (review loop, runtime/browser profiles), failure handling (CI failures, auto re-ticketing), and inline templates (worker-report.v1 JSON schema, Rich Completion Report). CC v2.1.32+ scales the skill character budget to 2% of the context window — large SKILL.md files are auto-trimmed, which means important routing info near the bottom can silently disappear. Splitting into references/ keeps SKILL.md as a slim routing index with the heavy content loaded on-demand. Templates folder isolates schema/format blocks that are emit/render targets, not narrative content.

**Source**: User request (this session) — *"refactor `@harness/skills/harness-work/`. each subcommand should live under references folder. anything shared between breezing skill and harness-work breezing should use shared reference located in breezing skill or directly call breezing skill. large reference text blocks should be under references too. for template blocks content, they should be under templates subfolder. the goal is to simplify this skill."* Vetted with the `Plan` advisor agent (Opus) — advisor flagged two corrections: (1) breezing skill is an *alias* delegating BACK to harness-work, so harness-work stays SSOT and breezing-mode flow extracts to `references/breezing-mode.md`, NOT deleted; (2) breezing/SKILL.md already cross-references harness-work's "Review Loop" and "Completion Report Format" — those pointers must be updated to the new file paths during the refactor.
